## Purpose of this note

This document records the rationale for creating Mode ID_4 and explains how it differs from existing Access-mode configurations.

It exists to support:
- traceability,
- future review, and
- audit clarity.

This note is descriptive, not normative.

---

## Why Mode ID_4 exists

Mode ID_4 was created to address a use case not fully covered by existing modes.

Specifically, this mode exists:

ID_4 exists to support exploratory, audience-specific reasoning that does not fit the constraints of ID_1, ID_2, or ID_3, while remaining non-authoritative.

ID_4 is intentional and scoped. It is not a temporary or ad-hoc variant.

---

## Comparison with existing modes

### Relationship to ID_1 — Core Workshop

- ID_1 focuses on foundational governance reasoning and shared language.  
  - ID_4 differs by emphasizing exploratory, audience-specific framing where shared learning language or workshop pacing is not the primary goal.

ID_4 does not replace ID_1.

---

### Relationship to ID_2 — Access-mode (Runtime Governance)

- ID_2 examines governance under operational and runtime conditions.
  - ID_4 differs by avoiding runtime assumptions, telemetry interpretation, or enforcement-adjacent reasoning unless explicitly declared in its README.


ID_4 does not assert runtime adequacy unless explicitly stated in its README.

---

### Relationship to ID_3 — Operator / Standards Mode

- ID_3 is inspection- and standards-facing.
  - ID_4 differs by supporting preparatory or explanatory inspection contexts without assuming formal standards submission or regulator-facing rigor.

ID_4 is not a standards submission unless explicitly designated.
