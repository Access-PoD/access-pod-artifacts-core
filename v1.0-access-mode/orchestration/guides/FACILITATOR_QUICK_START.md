# Facilitator Quick-Start Card — Access-mode v1.0

This card provides a rapid orientation for facilitators delivering the Access-mode workshop in any configuration.

For formal method definitions, see APOD-TR-006 (Version E)

---

## 1. Before the session (5 minutes)

Confirm:
- Audience type (general / practitioner / operator)
- Available time window
- Intended outcome (learning, analysis, inspection readiness)

Select **one Access-mode only** for a session.  
Do not mix modes unless explicitly designing a transition exercise.

---

## 2. Choose the Access-mode

Use this rule of thumb:

- **ID_1 — Core Workshop**  
  If the goal is shared understanding, fundamentals, or onboarding.

- **ID_2 — Access-mode (Runtime Governance)**  
  If the goal is to reason about governance under operational pressure.

- **ID_3 — Operator / Standards Mode**  
  If the goal is inspection, standards discussion, or regulator-facing artifacts.

Once selected, load modules from the corresponding folder only.

---

## 3. Facilitation posture by mode

### ID_1 — Core Workshop
- Ask “what does this mean?” questions
- Encourage discussion and reframing
- Avoid system-specific or compliance claims

### ID_2 — Access-mode
- Use scenarios and stress cases
- Ask “what changes under pressure?”
- Reinforce signal vs claim separation

### ID_3 — Operator / Standards
- Assume governance literacy
- Ask “how would this be inspected?”
- Focus on clarity, traceability, and defensibility

---

## 4. Timing discipline

- Follow the indicative timing guidance
- Do not rush Module 03 (evidence) or Module 06 (reflection)
- If short on time, **truncate discussion**, not structure

---

## 5. What not to do

- Do not imply certification, compliance, or approval
- Do not compare modes as “better” or “more mature”
- Do not modify canonical modules during delivery

---

## 6. Close the session

End by:
- Restating the **governance posture** used
- Naming what this mode **does not** cover
- Pointing to the next logical mode (if applicable)

Access-mode is about *selection*, not escalation.
