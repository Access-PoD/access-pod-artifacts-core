# Module 04 — regulator_evidence_requests (ID_3 Primer)

HASH KEY progression (1–10) is defined in the ID_3 control file and used consistently across modules.

Access-Mode context:
This module is rendered under **ID_3 — Inspection / Standards** posture.
It establishes evidence discipline for regulator-facing inspection artifacts.
No compliance, adequacy, certification, or approval claims are permitted.
Outputs remain draft, non-binding, and inspection-oriented.

---

## Purpose
Define how regulator-style evidence requests are interpreted, structured, and answered under inspection posture.

Evidence must be observable, traceable, and distinct from explanation.

Structural clarity does not create regulatory standing or imply compliance.

---

## Outcomes
By completing this module, the operator can:

- distinguish evidence from explanation and assumption  
- identify evidence gaps without inference  
- structure inspection responses defensibly  
- prevent AI from normalising missing artifacts  

---

## Inputs
- Module 01 identity boundaries complete  
- Module 02 language discipline active  
- Module 03 retrieval boundaries enforced  
- Defined governance scope  

If identity, language, or retrieval boundaries are unstable, pause.

### HASH KEY 5 — Evidence

Absence of evidence must be stated explicitly. Silence is not acceptable.

Define what counts as acceptable evidence:

- observable artifacts
- versioned documentation
- logs or records
- traceable governance decisions

Clarify what is not evidence:

- intentions
- plans
- assurances without artifacts
- AI-generated summaries without source

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Separate observable artifacts from narrative.

### Inspection risk
AI filling gaps with plausible language.

### Quality check
Could each claim be supported by a document or record?

</details>

### HASH KEY 6 — Method

Define response workflow:

1. Restate the question neutrally.
2. Classify request (evidence / explanation / assumption).
3. Identify artifacts.
4. Verify version and traceability.
5. Record gaps explicitly.
6. Structure response (evidence → explanation → assumption).

### HASH KEY 7 — Controls

Structural completeness of documentation does not imply adequacy or control effectiveness.

Define guardrails:

- Evidence precedes explanation.
- Each claim maps to an artifact.
- No inference fills gaps.
- AI may structure but not infer.
- Human review required before release.

### HASH KEY 8 — Failure Modes

- assurance language replacing observation
- partial artifacts treated as sufficient
- AI filling evidence gaps
- tone implying adequacy

Detection signals:
- “we ensure”
- “we comply”
- “best practice”
- missing artifact references
