# Module 03 — governance_rag_references (ID_3)

HASH KEY progression (1–10) is defined in the ID_3 control file and used consistently across modules.

All outputs remain draft, non-binding, and inspection-oriented.

---

## Purpose

This module establishes reference discipline and retrieval boundaries for AI-assisted governance work under ID_3 posture.

Unbounded retrieval introduces:

- authority drift  
- inference risk  
- silent sufficiency assumptions  
- inspection instability  

References must be bounded, classified, version-controlled, and explicitly weighted.

Structural referencing does not create normative authority.

---

## HASH KEY 1 — Retrieval Objective

References are retrieved only to:

- provide contextual grounding  
- support structural explanation  
- improve standards literacy  

References must not be used to:

- determine obligation  
- assert compliance  
- establish adequacy or sufficiency  
- substitute human judgment  

If the purpose of retrieval cannot be stated explicitly, retrieval must not proceed.

---

## HASH KEY 2 — Reference Categories

Only explicitly permitted categories may be used.

**Permitted categories:**

- Formal standards (e.g. ISO, IEC)  
- Statutory or regulatory texts (contextual reference only)  
- Official regulatory guidance and consultation drafts  
- Internal governance frameworks  
- Prior documented governance decisions  

**Disallowed categories:**

- Blogs or commentary  
- Vendor marketing materials  
- Unofficial summaries without primary citation  
- AI-generated interpretations presented as authority  
- Informal presentations or social media posts  

References outside permitted categories must not be used.

Inspection stability depends on explicit exclusion.

---

## HASH KEY 3 — Authority Weighting

Each reference must be assigned an explicit authority level.

### Primary authority

- Formal standards  
- Statutory or regulatory texts  

Permitted use:
- literal citation  
- contextual explanation  
- structural comparison  

Prohibited use:
- inferring applicability  
- asserting compliance  
- declaring sufficiency, adequacy, or approval  

---

### Secondary authority

- Official regulatory guidance  
- Consultation drafts  
- Standards body explanatory materials  

Permitted use:
- contextual clarification  

Prohibited use:
- overriding primary authority  
- being treated as mandatory  

---

### Contextual authority

- Internal frameworks  
- Prior governance decisions  
- Academic analysis (when cited)  

Permitted use:
- structural reference  
- comparison  

Prohibited use:
- establishing obligation  
- implying compliance  
- being treated as authoritative  

Authority must never be inferred from tone, familiarity, repetition, or formatting.

If authority level cannot be assigned, the reference must not be used.

---

## HASH KEY 4 — Interpretation Boundaries

AI-assisted interpretation is limited to:

- literal reading  
- contextual explanation  
- structural comparison  
- faithful summarisation  

AI must not:

- extend or reinterpret obligations  
- infer applicability, adequacy, or sufficiency  
- harmonise requirements across standards  
- resolve ambiguity  
- decide between conflicting interpretations  

Ambiguity must be surfaced, not resolved.

Inspection posture requires visible interpretive restraint.

---

## HASH KEY 5 — Version & Currency Control

Each reference must include:

- version or edition  
- publication date (where applicable)  
- status (current, superseded, draft, consultation)  

Prohibited practices:

- unversioned references  
- mixing versions without disclosure  
- treating drafts as final authority  
- allowing AI to substitute newer versions silently  

AI must preserve operator-specified versions.

If currency cannot be confirmed, the limitation must be recorded.

Structural citation without version control is unstable.

---

## HASH KEY 6 — Retrieval Boundary (Critical Control)

AI retrieval is limited to:

- operator-provided documents  
- explicitly approved reference sets  
- formally cited standards supplied by the operator  

AI must not:

- access external sources without explicit authorization  
- introduce uncited references  
- expand scope autonomously  
- fill gaps using general knowledge  
- introduce “best practice” claims without citation  

External retrieval, if enabled, must be:

- explicitly authorized  
- logged  
- reviewable  
- classified under authority rules  

All references used must be traceable and reviewable.

---

## HASH KEY 7 — Reference Mapping

For each reference used, record:

- reference identifier  
- category  
- authority level  
- permitted use  
- version status  

No reference may remain unclassified.

If a reference cannot be clearly bounded, drafting must pause.

Inspection defensibility depends on explicit mapping.

---

## HASH KEY 8 — Drift Detection

Drift indicators include:

- phrases such as “best practice suggests”  
- uncited obligation language  
- elevation of contextual sources into normative position  
- AI introducing general knowledge without citation  
- authority inversion across documents  
- sufficiency language without authority declaration  

Detected drift requires:

- reclassification  
- citation requirement  
- qualification  
- or removal  

Drift must be corrected before progression.

---

## HASH KEY 9 — Boundary Confirmation

Confirm:

- Reference scope is explicit.  
- Authority hierarchy is documented.  
- Version control is applied.  
- Retrieval boundaries are enforced.  
- Interpretation limits are respected.  
- AI cannot expand its reasoning base silently.  

If any control cannot be confirmed, progression must pause.

---

## HASH KEY 10 — Readiness

Readiness score:

- 1  
- 2  
- 3  
- 4 x  
- 5  

5 — Reference scope and retrieval discipline are stable and consistently enforced.  
4 — Core controls exist; minor refinement required.  
3 — Authority conflicts or retrieval drift remain possible.  
2 — Informal sources influence reasoning.  
1 — Reference discipline is unstable.

Progress only when retrieval boundaries and authority controls are explicit and stable.
