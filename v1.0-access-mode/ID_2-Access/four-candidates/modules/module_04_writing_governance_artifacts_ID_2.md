# Module 4 — Writing Governance Artifacts with AI
## Neutrality, Evidence, and Audit Defensibility

HASH KEY progression (1–10) is defined in the README_ID_2 and used consistently across modules.

Access-Mode context:
This module is rendered under **ID_2 — Operational / Runtime Reasoning** posture.
Written artifacts capture scenario-based operational reasoning and observed signals.
They do not constitute final governance determinations or inspection-ready conclusions.

---

## Purpose

This module focuses on producing governance artifacts with AI support
*without compromising neutrality, evidentiary discipline, or accountability*.

The primary risk is not incorrect language — it is **tone drift**, **implicit recommendation**, or **unverifiable reasoning**.

---

## HASH KEY 1 — Purpose of the Artifact

Complete:
> “The purpose of this artifact is to…”

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Lock the **function of the document** before any drafting begins.

### Good answer shape
- One clear purpose
- Describes what the artifact is for, not what it contains
- Distinguishes explanation from influence

### Strong framing pattern
> “The purpose of this artifact is to ___, not to ___.”

### Common failure modes
- Treating purpose as “to document everything”
- Allowing the artifact to imply recommendation or decision
- Letting audience expectations define purpose implicitly

### Quality check
If this document were quoted out of context, would its purpose still be clear?  
If yes → purpose is stable.

</details>

## HASH KEY 2 — Intended Audience & Reading Context

Complete:
> “This document is written for…”

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Shape tone and evidentiary discipline by being explicit about **who will read this**.

### Good answer shape
- Named audience(s)
- Acknowledges scrutiny level
- Anticipates adversarial or secondary readers

### Common failure modes
- Writing for “everyone”
- Assuming shared context
- Forgetting downstream readers (audit, inquiry, regulator)

### Quality check
Would the tone change if the audience changed?  
If yes → audience matters and must be explicit.

</details>

## HASH KEY 3 — Acceptable Language and Tone

List:
- language styles to avoid,
- language styles that are acceptable.

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Prevent **tone drift** before it happens.

### Good answer shape
- Lists language to avoid
- Lists acceptable constructions
- Anchors tone to neutrality and description

### Strong indicators
- “Descriptive, not persuasive”
- “Conditional, not declarative”
- “Evidence-referenced, not inferential”

### Common failure modes
- Assuming neutrality is automatic
- Allowing confident phrasing to stand unchallenged
- Copying tone from persuasive documents

### Quality check
Could any sentence be mistaken for a recommendation?  
If no → tone is controlled.

</details>

## HASH KEY 4 — Evidence Expectations

Complete:
> “Claims in this document must be supported by…”

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Define **what counts as support** for claims before drafting.

### Good answer shape
- Clear definition of acceptable evidence
- Distinguishes reference, citation, and assumption
- Rejects unsupported inference

### Common failure modes
- Treating AI fluency as evidence
- Allowing implied facts
- Mixing observation with conclusion

### Quality check
Could every claim be traced to a source or observation?  
If yes → evidence discipline is sound.

</details>

## HASH KEY 5 — Drafting vs Finalization Boundary

Complete:
> “AI-generated drafts are acceptable for…”

and
> “Final artifacts require…”

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Prevent **draft leakage** into authoritative use.

### Good answer shape
- Clear distinction between exploratory drafts and final artifacts
- Explicit criteria for finalization
- Names what must be removed or tightened

### Common failure modes
- Treating drafts as “good enough”
- Forgetting to remove exploratory language
- Allowing AI-generated text to persist unreviewed

### Quality check
Could a draft be mistaken for a final artifact?  
If no → boundary is enforced.

</details>

## HASH KEY 6 — AI Assistance Boundary in Writing (Critical Control)

Complete:
> “AI may assist with writing by…”

Explicitly exclude interpretation, recommendation, risk acceptance.

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Set a **hard limit** on what AI may do in writing.

### Good answer shape
- Explicitly allowed assistance (structure, language refinement)
- Explicitly prohibited actions (interpretation, recommendation)
- Task-specific, not generic

### Required framing
> “AI may assist with writing by ___, but must not ___.”

### Common failure modes
- Allowing AI to shape meaning
- Treating review as a substitute for boundaries
- Vague or over-broad permissions

### Quality check
If AI crossed this boundary, would it be immediately obvious?  
If yes → boundary is clear.

</details>

## HASH KEY 7 — Exercise: Paragraph Discipline

1. Draft one governance paragraph with AI assistance.
2. Identify:
   - implied recommendation,
   - unreferenced claims,
   - tone drift.
3. Rewrite to remove all three.
4. Keep both versions and annotate what changed.

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Train detection of **implicit inference and advocacy**.

### Good answer shape
- Side-by-side draft and revised paragraph
- Annotations explaining changes
- Focus on removal, not embellishment

### Common failure modes
- Editing for style only
- Leaving inference unchallenged
- Discarding the original draft

### Quality check
Could the revised paragraph withstand adversarial reading?  
If yes → the exercise worked.

</details>

## HASH KEY 8 — Case Prompt (Audit Stress Test)

A reviewer asks:
> “Can you show how this conclusion was reached?”

- Which sentences are defensible?
- Which rely on inference?
- What evidence trail exists?

Write a short response indicating what you can defend and what you would revise.

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Stress-test **defensibility**, not correctness.

### Good answer shape
- Identifies which sentences are defensible
- Identifies which require revision
- Refers to evidence trail, not authority

### Common failure modes
- Defending everything
- Treating questions as attacks
- Assuming reviewer intent

### Quality check
Could you show how the text was constructed line by line?  
If yes → defensibility exists.

</details>

## HASH KEY 10 — Priority & Output Readiness Rating

**Readiness score:** 

1 ☐ 
2 ☐ 
3 ☐ 
4 ☐ 
5 ☐

- What weakens this score?
- What safeguards are missing?
- What must change before issuing a final artifact?

<details>
<summary><strong>PRIMING — How to approach this section (delete before finalising)</strong></summary>

### Intent
Gate **issuance readiness**, not writing confidence.

### Good answer shape
- One score selected (1–5)
- Justified in plain language
- Names what must change before issuance

### Common failure modes
- Treating “5” as success
- Using score defensively
- Equating fluency with defensibility

### Quality check
Would you delay issuing the artifact if the score were low?  
If yes → the rating is honest.

</details>
