# Release Notes — Access-Mode ID_1 (Core / Learning)

## Release purpose

This release publishes the **ID_1 — Core / Learning** mode of the Access-Mode method
as a complete, standalone learning workspace.

ID_1 establishes disciplined AI governance reasoning **before**:
- runtime operation,
- system deployment,
- regulatory inspection,
- or standards assessment.

> All content in this release is **learning-oriented, non-operational, and non-inspectable**.  
> Operational (ID_2) and inspection (ID_3) Access-Modes are separate releases and are **not included** at the time of this publication.

---

## Getting Started

- This release is **learning-only (ID_1)** — no operation, no inspection.
- Start with the **priming modules** in `/modules/` and fill them with your own inputs.
- Use the **exemplar modules** in `/exemplar_modules/` as a reference for tone, structure, and boundaries.
- Keep priming and exemplar modules in **separate projects**.
- Compare your filled priming modules against the exemplars to refine reasoning and discipline.

A PDF version of these release notes is provided for reading convenience only.
The Markdown file remains the canonical reference.

---

## What this release contains

This release includes **two complementary module sets**, both governed by
**Access-Mode ID_1**:

### 1. `/modules/` — Priming modules (primary use)

The `modules/` folder contains the **priming version** of the six ID_1 modules.

These modules:
- include structured guidance on *how to reason*,
- contain prompts, exercises, and boundary framing,
- are designed to be used directly in a learning project,
- represent the **optimal default** for most users.

**Use these modules when you want to:**
- learn AI governance reasoning from first principles,
- explore scope, intent, references, and drafting discipline,
- interact with the AI system and generate your own answers,
- validate your understanding through comparison and reflection.

---

### 2. `/exemplar_modules/` — Worked examples (instructional reference only)

The `exemplar_modules/` folder contains **worked examples** of the same six modules.

These exemplars:
- show *what a well-disciplined ID_1 fill looks like*,
- are concise and stripped of priming scaffolding,
- demonstrate posture, tone, and boundary discipline,
- are published as **Working-PoD examples for instruction only**.

**Important:**
- Exemplars are **not templates** to copy verbatim.
- Exemplars are **not inspectable artifacts**.
- Exemplars must **not** be reused as operational or review material.

They exist to:
- orient facilitators,
- support learning comparison,
- and illustrate disciplined outcomes under ID_1 posture.

## Using priming and exemplar modules together

This release includes two complementary module sets:

- **`/modules/` — Priming modules**  
  Intended for **active learning**. Users are expected to fill these modules with their own inputs.

- **`/exemplar_modules/` — Worked examples**  
  Concise, instructional examples of a completed ID_1 Working-PoD, provided for **reference only**.

For best results:
- use **one module set per project**,
- compare your filled priming modules against the exemplar modules,
- do not mix the two sets in the same project,
- and do not reuse exemplar content as operational or inspectable material.

The priming modules are intentionally more expansive to support learning.
The exemplar modules demonstrate what a **disciplined, concise ID_1 result** looks like.

## How to use this learning mode effectively

### Recommended usage pattern

This learning mode is designed to be used with **both module sets**, in a
deliberate sequence that supports learning, comparison, and refinement.

1. **Start by opening both versions of Module 01**:
   - the priming version from `/modules/`, and
   - the worked example from `/exemplar_modules/`.

   Read the exemplar first to understand the expected posture, tone, and
   boundary discipline under Access-Mode ID_1.  
   Then begin filling the corresponding priming module with your own inputs.

2. **Work through the priming modules (`/modules/`) sequentially**:
   - complete all six modules using your own reasoning,
   - let the AI assist only within ID_1 boundaries,
   - answer prompts, complete exercises, and write reflections in full.

   The priming modules are intentionally more expansive to support learning
   and to surface assumptions, scope drift, and tone issues early.

3. **Create two separate learning projects for comparison**:
   - **Project A (primary learning project):**  
     upload your completed priming modules from `/modules/`.
   - **Project B (reference project):**  
     upload the worked exemplar modules from `/exemplar_modules/`.

   Use the exemplar project as a **comparison reference** to:
   - identify differences in structure, tone, and boundaries,
   - see where your reasoning drifted or over-asserted,
   - refine your priming modules while keeping them your own.

This comparison is **intentional and encouraged**.  
It is a learning technique, not an evaluation or validation step.

The priming modules should remain your **active working set** for ID_1 learning.
The exemplar modules should be treated as **instructional Working-PoDs only**,
used to orient and calibrate—not to copy or operationalize.

## Using both sets as comparative learning tools

Both module sets may be used to run **separate learning projects**:

- Project A: your own reasoning using `/modules/`
- Project B: review-only reading using `/exemplar_modules/`

Comparing outputs across the two projects helps surface:
- hidden assumptions,
- tone drift,
- scope expansion,
- or implicit authority creep.

This comparison is a **learning technique**, not an evaluation.

## Relationship to other Access-Mode releases

- This release implements **Access-Mode ID_1 (Core / Learning)** only.
- Operational reasoning (ID_2) and inspection reasoning (ID_3) are **separate releases** and are not included at the time of this publication.
- For the complete, unfilled template module sets covering **ID_1, ID_2, and ID_3**, refer to the **v1.0-access-mode** release.

Each Access-Mode must be used in a **separate project**, according to its declared posture.

### Note on exploratory and custom modes (ID_4)

The **v1.0-access-mode** release also documents an optional **custom exploratory mode (ID_4)**.

ID_4 is **not a canonical Access-Mode** and is **not included** in this ID_1 release.  
It exists to support **explicit, time-bounded experimentation** where the standard modes
(ID_1, ID_2, ID_3) do not cleanly apply.

Guidance for ID_4:
- is provided in the **v1.0-access-mode** release,
- requires explicit purpose and boundary declaration,
- must remain non-authoritative and non-inspectable,
- must never be used for operational, inspection, or decision-adjacent work.

ID_4 does not extend, modify, or replace the Access-Mode method defined in **APOD-TR-006 (Version E)**.

### Canonical module templates and instructions

The **v1.0-access-mode** release contains the **canonical, unfilled module templates**
for Access-Mode **ID_1, ID_2, and ID_3**.

Specifically:
- the folder `v1.0-access-mode/modules/` holds the **canonical module definitions**, and
- instructions for safely copying these templates (including *robocopy-only guidance*)
are documented in the accompanying PDF materials.

These canonical modules and instructions are published in the
**v1.0-access-mode** release on GitHub:

https://github.com/Access-PoD/access-pod-artifacts/releases/tag/v1.0-access-mode

This **ID_1 — Core (Learning)** release provides **working learning materials and examples**
derived from those canonical templates. It does not replace or redefine them.
