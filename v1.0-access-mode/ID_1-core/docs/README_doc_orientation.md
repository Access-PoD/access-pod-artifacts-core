# Access-Mode Papers — How to Read This Release

This folder contains the canonical Access-Mode papers provided for reference
with the Access-Mode ID_1 — Core (Learning) release.

These papers explain **how AI reasoning is constrained and interpreted** when working
with governance materials. They are non-normative and do not assert compliance,
certification, or deployment readiness.

---

## Included Papers

### APOD-TR-006 — Version E  
**Access-Mode Method (Reasoning Orchestration)**

This is the **canonical method paper**.

Read this paper to understand:
- why reasoning posture matters in AI-assisted governance,
- how learning, operational, and inspection reasoning are explicitly separated,
- the rules governing primary and secondary Access-Modes,
- validation discipline (including misalignment testing),
- and the non-normative scope of the method.

Version E defines **how reasoning is controlled**.
It does not describe artifact lifecycle or release mechanics.

---

### APOD-TR-006-E.2 — Version E.2  
**Artifact Lifecycle Companion (Working-PoDs)**

This is an **informative companion** to Version E.

Read this paper to understand:
- how governance artifacts move from draft to inspection-ready states,
- how “filled” means different things under ID_1, ID_2, and ID_3,
- when artifacts may be considered frozen for inspection,
- and how example Working-PoDs should be interpreted safely.

Version E.2 explains **what an artifact represents at a given point in time**.
It does not modify or extend the Access-Mode method.

---

## How These Papers Relate

- **Version E** answers: *“What kind of reasoning is permitted here?”*  
- **Version E.2** answers: *“What does this artifact represent at this stage?”*

They are designed to be read together, but **Version E remains the authoritative method**.

---

## Project Setup and Use

For practical instructions on how to **set up and run AI projects** using Access-Mode
(single-mode and mixed-mode), refer to:

**Access_Mode_Project_Guide.pdf**

The Project Guide defines:
- required files,
- project configuration rules,
- mode discipline during use,
- and validation and record-keeping practices.

Where guidance differs, the **Project Guide governs setup**, and **Version E governs
method interpretation**.

---

## Important Notes

- These papers are **informative and methodological**.
- They do not define requirements, controls, or conformance criteria.
- Outputs generated using Access-Mode remain drafts and require human judgment.
- Access-Mode constrains reasoning posture; it does not grant authority.

---

## Suggested Reading Order

1. **Version E** — understand the method  
2. **Project Guide** — learn correct project setup  
3. **Version E.2** — understand artifact lifecycle and inspection readiness
