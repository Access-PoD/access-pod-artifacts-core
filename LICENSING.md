## Verified source evidence and preserved history

On 11 October 2026, the repository snapshots resolved by all nine selected release tags contained the same MIT `LICENSE` file: `v1a`, `v1b`, `v1c`, `v1d`, `v1.0-access-mode`, `ID_1-core`, `ID_2-Access`, `ID_3-operator` and `APOD-ID3-RULE-001-v1.1`. The MIT notice retained here is byte-identical to the licence embedded in the v1a artifact ZIP; its text matches those tag-level files, with only line endings differing. The other eight preserved curated ZIPs contain no licence file. Repository snapshots and curated release assets are distinct evidence objects; absence of a licence file within a ZIP does not by itself establish absence of licensing.

The current [repository README](https://github.com/Access-PoD/access-pod-artifacts-core/blob/main/README.md) describes earlier releases as MIT-licensed, while [LICENSE_HISTORY.md](https://github.com/Access-PoD/access-pod-artifacts-core/blob/main/LICENSE_HISTORY.md) describes v1b–v1e and related material as lacking an explicit repository licence and says later licensing is not retroactive. This documentary conflict remains visible in the preserved source records. The current tag observations do not reconstruct the complete licensing chronology or the state of tags at initial publication. The [repository licence](https://github.com/Access-PoD/access-pod-artifacts-core/blob/main/LICENSE) and each component's source note provide the upstream context.

Original ZIPs, source notices, checksums and dated preparation records under `provenance/` remain unchanged historical evidence. Their contents are not silently rewritten to describe this consolidation's current grant. The separately named current notes explain the distinction.

## Reuse and interpretation

Preserving an original baseline is a reproducibility practice, not an additional prohibition on modification under MIT. Modified copies should be described accurately in relation to their preserved sources. Retain the copyright and permission notice as required by the licence.

Licensing concerns reuse. It does not confer governance adequacy, regulatory approval, certification, deployment authority or evidence that a workflow has run in a new environment.
